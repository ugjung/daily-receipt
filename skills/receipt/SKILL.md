# 오늘 한 일 영수증

Claude Code 대화 기록(~/.claude/projects)에서 그날 한 일을 추려 영수증 한 장으로 만든다.

아래 `<스킬폴더>`는 이 스킬을 불러올 때 표시되는 Base directory다(그 안에 scripts/가 있다). Windows에서는 `python`, macOS에서는 `python3`를 쓴다.

## 지켜야 할 것 (안전)

- **읽기만 한다.** 대화 기록(~/.claude/projects)과 메모리 파일은 읽기만 하고 절대 고치거나 지우지 않는다. 이 작업 중에 메모리를 새로 저장하지도 않는다.
- **쓰는 곳은 한 군데.** `~/Documents/claude-receipts/` 안의 그날 json, html만 만든다. 다른 폴더, 다른 파일은 건드리지 않는다.
- **밖으로 보내지 않는다.** 영수증 내용을 Slack, Notion, 메일 등 외부로 올리지 않는다. 사용자가 그 자리에서 직접 요청할 때만 예외.
- **영수증 문구에 넣지 않는 것**: 비밀번호, 키, 토큰, URL, 이메일, 전화번호, 서버 주소, 동료 실명(필요하면 "담당자"), 계약 금액 같은 숫자. collect 결과에 [가림], [링크] 같은 표시가 있으면 그 부분은 무시한다.

## 순서

1. **수집**: `python "<스킬폴더>/scripts/collect.py" [YYYY-MM-DD]`
   날짜를 안 주면 오늘(KST). 세션마다 제목과 요청(prompts) 목록이 나온다. 요청 하나하나에 시각(time), 그 요청 뒤로 이어진 작업 분(min), 그 사이 수정한 파일(files)이 붙어 있다. 여러 창을 동시에 쓴 시간은 그때 돌던 요청들끼리 나눠서 셌기 때문에, 모든 min을 더하면 total_active_min(겹침 없이 실제로 쓴 시간)과 같다. 맨 위 `models`는 그날 쓴 모델별 응답 수.
2. **추리기**: 아래 규칙으로 영수증 JSON을 쓴다. 저장 위치는 `~/Documents/claude-receipts/YYYY-MM-DD.json`.
3. **렌더링**: `python "<스킬폴더>/scripts/render.py" <json경로>` → 같은 폴더에 `YYYY-MM-DD.html`.
4. **열기**: 대화형 세션이면 브라우저로 연다(Windows `Start-Process "<html경로>"`, macOS `open "<html경로>"`). 인자에 `scheduled-run`이 있으면 예약 실행이다. 이때는 열지 말고 경로만 출력한다(예약 스크립트가 연다).
5. 사용자에게는 품목 이름만 한 줄씩 짧게 알려 주고 경로를 준다.
6. collect 결과의 sessions가 비었거나 collect.py를 실행할 수 없으면 아래 "Claude Code 기록이 없을 때"로 간다.
7. `~/.claude/daily-receipt/config.json`이 없고 대화형 세션이면, 끝에 한 줄로 "`/daily-receipt:setup`으로 이름과 자동 실행을 설정할 수 있어요"라고 안내한다.

## Claude Code 기록이 없을 때 (Cowork, 데스크톱 앱 사용자)

Cowork나 데스크톱 앱에서는 ~/.claude/projects가 비어 있거나 볼 수 없을 수 있다. 그때는 이 순서로 재료를 모은다.
1. 지난 대화나 지난 작업 세션을 검색하는 도구가 있으면 그것으로 그날 대화와 작업을 모은다.
2. 지금 세션에서 그날 한 일도 포함한다(영수증 요청 자체는 뺀다).
3. 둘 다 없으면 지어내지 말고 "오늘 한 일을 몇 줄로 적어 주시면 영수증으로 만들어 드릴게요"라고 묻는다. 예약 실행이면 "오늘 볼 수 있는 기록이 없어요"라고만 남긴다.

이 경우 메시지 시각을 알면 minutes(5분 넘는 간격은 5분)로, 모르면 시간을 추측하지 말고 품목마다 `chats`(대화 수)를 쓴다. 영수증은 render.py로 만들어도 되고(minutes 대신 chats도 받는다), 파이썬을 못 쓰면 `<스킬폴더>/assets/receipt-template.html`의 `id="data"` JSON만 바꿔서 만든다. 파일로 저장할 수 있으면 `~/Documents/claude-receipts/YYYY-MM-DD.html`, 아니면 HTML 아티팩트나 작업 폴더에 저장해서 보여 준다.

## 추리기 규칙 (핵심)

**품목은 일 단위로, 보통 5~10개.** 세션 하나가 품목 하나가 아니다.
- **긴 세션은 쪼갠다.** 한 세션 안에서도 요청 흐름이 바뀌면(기획 → 수집기 코딩 → 대시보드 → 문서 정리) 각각 별도 품목이다. 바뀌는 지점은 요청 내용, 수정 파일 종류(.py / .md / .html), 대상 산출물이 달라지는 곳으로 판단한다.
- **흩어진 같은 일은 합친다.** 다른 세션이나 떨어진 시간대에 같은 산출물(같은 파일, 같은 시트, 같은 문서)을 다뤘으면 하나로.
- 품목의 분(minutes)은 해당 요청들의 min을 더한 값이다. 모든 품목 분의 합이 total_active_min과 크게 어긋나지 않게 한다(버린 잡무만큼만 차이).
- 5분 미만으로 끝난 잡무(링크 설명, 경로 묻기, 설정 확인)는 "기타 잡무" 하나로 묶는다. 묶어서도 5분 미만이면 뺀다.
- 결과가 없던 탐색은 "OO 검토"처럼 정직하게 적는다.
- 시간 순서대로 나열한다(같은 프로젝트끼리는 렌더러가 모아 준다).

**프로젝트(group)**: 같은 프로젝트 품목에는 같은 짧은 이름(8자 안팎)을 붙인다. 예: "광고주발굴", "SF-모비사인". 렌더러가 프로젝트별로 묶고 소계를 보여 준다. 혼자인 품목은 비워 둬도 된다.

**종류(kind)**: 기획, 분석, 개발, 문서, 데이터, 검수, 조사, 운영 중 하나(2~3자).

**품목 이름(name)**: 12자 안팎 명사구. 프로젝트 이름은 group에 있으니 반복하지 않는다.
- 좋음: "성사DB 심층 분석", "영수증 스킬 제작", "회의록 3건 정리"
- 나쁨: "광고 수요 신호 기반 타깃 자동 발굴 MVP 관련 작업"(길다), "분석"(모호)

**결과(done)**: 한 줄, 25자 안팎. 산출물 중심 "ㄱㄱㄱ" 톤. 동사는 끝에 짧게.
- 좋음: "파레토, RFM, 군집 분석 보고서 완성", "수집기와 렌더러 작성, 테스트 통과"
- 사실만 쓴다. files, 요청 흐름에서 확인되는 것만. 기록에 없는 성과를 지어내지 않는다.

**내일로 이월(carry_over)**: 0~3개. 마지막 요청이 답 없이 끝났거나, "추후", "대기", "다음에" 같은 말이 나온 것만. 없으면 빈 배열.


**표기**: 가운뎃점(·) 쓰지 않는다. 쉼표나 "와/과"로 푼다.

## 영수증 JSON 형식

```json
{
  "date": "2026-10-14",
  "weekday": "수",
  "models": {"claude-opus-5-5": 288, "claude-fable-5-1": 148},
  "items": [
    {"group": "광고주발굴", "kind": "분석", "name": "성사DB 심층 분석", "minutes": 28, "done": "파레토, RFM, 군집 분석 보고서 완성"}
  ],
  "carry_over": ["사람인 API 연동 (API 제공 대기)"]
}
```

- `store`(상호), `customer`(고객)는 넣지 않는다. 렌더러가 `~/.claude/daily-receipt/config.json`에서 읽고, 없으면 OS 사용자명을 쓴다.
- `models`는 collect 결과의 `models`를 그대로 옮긴다. 렌더러가 결제수단 여러 줄로 보여 준다.
- 사용시간 표기(29분, 1시간 12분), 총 사용시간, 승인번호(만든 날짜시각 14자리)는 렌더러가 계산한다.

## 기록이 없을 때

collect 결과 sessions가 비었으면 영수증을 만들지 말고 "오늘은 Claude 기록이 없어요"라고만 답한다.
